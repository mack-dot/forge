SUMMARY OF ANSWERS TO THE SIX QUESTIONS
==================================================================================================================
Q1 TOCTOU / CDHash. The in-scope TOCTOU (file at the caller path changes) is removed by L2+L3 (bytes read once,
   private copy written from the same memory bytes). That part is sound by reading. L7 (csops CDHash) only defends
   the private copy between L3 and exec, and only a same-uid or root writer can touch that copy (mkdtemp 0700).
   The matrix puts that adversary OUT of scope. The AC2-m test does not race anything. See F-04.
   CDHash coverage (codesign_orig.log: CodeDirectory flags adhoc,linker-signed, hashes=58+0, page 4096): the code
   directory holds one SHA-256 per 4 KiB page over [0, codeLimit), so it binds every file byte before the
   signature (all segments, header, __DATA file contents, __LINKEDIT up to the signature); 0 special slots.
   It does NOT bind memory after exec: pages are validated lazily at page-in, and L7 reads CS_VALID once.
   Timing: Popen returns only after the CLOEXEC errpipe closes, i.e. after execve, so csops sees the new image
   (BY READING of subprocess.py 1720-1783). L7 runs before any request byte (launcher.py 356-359 before 369).
Q2 Environment. Child env is exactly empty (env={} -> execve envp empty; launcher.py 351). -I removes PYTHON*,
   user site and script dir, but NOT system site .pth files (F-11). DYLD_* against the shim is pruned by the OS
   (AC2-n1), so L0 never fires in a real run (F-10). DEVELOPER_DIR: the `env -i` rule is not enforced by anything
   (F-05). TMPDIR: ignored (mkdtemp dir= is explicit, 445). Locale: no locale-dependent code path found.
Q3 Descriptors/signals/limits. Child: fds 0..2 only, SIG_DFL, empty mask, setsid, RLIMIT_CORE 0. Launcher
   ITSELF inherits caller signal dispositions (F-01: SIGCHLD), caller rlimits (T-1, OPEN), caller Mach
   exception/special ports (F-03, not in matrix), caller controlling terminal (safe direction). umask: no effect
   (fchmod/chmod are explicit). ptrace/task port by same uid: out of scope and the matrix says so (N19, T-2).
Q4 Accept rule. strict_parse/_strict_atom/make_str_safe/render_* in launcher.py 69-176 are the same logic as
   frame.py 25-63, 199-260 (line-by-line compare; only comments and statement layout differ). decide_from_result

F-01  HIGH  launcher.py:404-421 (+ CPython subprocess.py:1872-1883 _try_wait, 1847-1866 _internal_poll)
  What  : The launcher never resets its OWN SIGCHLD disposition. execve keeps SIG_IGN (man 2 execve: "Signals set
          to be ignored in the calling process are set to be ignored in the new process"); CPython does not
          reset SIGCHLD at start. If the caller starts the launcher with SIGCHLD = SIG_IGN (or SA_NOCLDWAIT),
          the kernel may auto-reap the child, waitpid fails with ECHILD, and CPython's _try_wait then sets
          sts = 0 ("This child is dead, we can't get the status"). p.returncode becomes 0 for ANY child end:
          exit 3, exit 1, SIGABRT, SIGKILL, SIGSEGV. spawn_and_collect then reports exit_code=0, signal=None.
  Why   : D2 ("ended by signal") and D3 ("exit code is not 0") are silently disabled. The docstring L12 "accept
          ONLY exit 0" and the matrix L10 "exit code or signal is recorded" are false in that caller state.
          "Ignored or blocked signals" is IN the matrix's adversary scope (section 3). `env -i` does not reset
          signal dispositions, so the invocation rule does not help.
  Impact: A wrong AUTHORIZED still needs stdout == expected_accept (D11) and empty stderr. So the impact is: any
          run that wrote the exact accept frame and then ended abnormally (crash after the last write, CPU-limit
          kill, abort in an exit path, X8 C4 killed-run clause) is accepted as a normal halt. Whether the pinned
          program has such a run is UNSURE. The control claim is broken regardless.
  UNSURE: XNU auto-reap for SIGCHLD = SIG_IGN (SA_NOCLDWAIT is documented in man 2 sigaction lines 102-109; plain
          SIG_IGN is not stated there). Also UNSURE whether the /usr/bin/python3 shim resets dispositions.
  Run that decides: from a caller that sets signal(SIGCHLD, SIG_IGN) (and, separately, SA_NOCLDWAIT) then
          execs `/usr/bin/env -i /usr/bin/python3 -B -I launcher.py`, launch a pinned TEST executable that
          writes the exact accept frame and then exits 7 (and one that then raises SIGABRT). Expected if the
          finding holds: decision AUTHORIZED, exit 0. Fix: in the launcher, before Popen, set SIGCHLD to SIG_DFL
          with no SA_NOCLDWAIT (signal.signal(SIGCHLD, SIG_DFL)), and treat ECHILD as REFUSED (call os.waitpid
          directly instead of Popen.wait).
  Matrix: add a row (caller SIGCHLD SIG_IGN / SA_NOCLDWAIT) = OPEN. Narrow L12/D2/D3 claims. AC3-i ("REFUSED D2")
          holds only when SIGCHLD is not ignored in the launcher. N14 row: the launcher enforces SIG_DFL in the
          CHILD only, not in itself.

F-02  MED   launcher.py:374-380 (blocking os.write, no deadline), 183-194 (no size bound), 288 (open blocks)
  What  : (a) The request is written with ONE blocking os.write of the whole wire (feed_chunk=0). Comment 377
          says "a small request fits the pipe buffer", but check_request bounds no length (charge/request ids
          are unbounded bytes). If the request exceeds the pipe capacity (16 KiB default, up to 64 KiB) and the
          child does not drain stdin, the launcher blocks inside os.write; the deadline (369-373) is not checked
          while blocked. If the child writes more than the stdout or stderr pipe capacity before it has read all
          of stdin, both sides block: deadlock. No time-out, no kill, no decision line.
          (b) L1 os.open(path, O_RDONLY|O_NOFOLLOW) on a FIFO placed at the caller path blocks forever before
          the S_ISREG check (293). "A replaced file at the path" is in scope.
  Why   : L9 "Time limit: kill the session" is not true for the write phase or for L1/L2. Fail-safe for
          authorization (no line = REFUSED by the consumer rule), but a hang, and the consumer in tests/common.py
          has a time-out only because the test adds one.
  UNSURE: whether the pinned CakeML program reads all of stdin before its first write. Run that decides: launcher
          with a 1 MiB charge id; launcher with a FIFO at --exe.
  Fix   : non-blocking stdin pipe + select-driven write (as _write_all_to already does), a size bound on the
          request, O_NONBLOCK on the L1 open (then fstat before read).
  Matrix: add a row (large request / FIFO at the path: hang, no decision) = OPEN. AC3-h and N20 are unaffected
          for small requests only; say "requests below the pipe capacity".

F-03  MED   launcher.py:312-322 (_child_setup), 350-352; CONTROL_MATRIX.md section 3
  What  : Task-level Mach exception ports (and other task special ports, e.g. the bootstrap port) are inherited
          across fork and, for a non-setuid image, kept across exec. A caller can install an exception port on
          its own task, then exec the launcher; the launcher and the child inherit it. On any Mach exception in
          the child (EXC_BAD_ACCESS, EXC_BREAKPOINT, EXC_CRASH), an EXCEPTION_DEFAULT message carries the child's
          thread and task ports to the caller's handler, which can then change registers and memory and resume
          the child (forged frame, exit 0). The caller can provoke an exception with a caller-set rlimit
          (RLIMIT_STACK small; T-1 is OPEN and the launcher resets only RLIMIT_CORE).
  Why   : This is a pre-exec state set by the CALLER (in scope by section 3 wording), not a debugger attaching
          later (out of scope). The matrix and N19 discuss debuggers and task ports "during or after exec"
          only; this path is not listed anywhere.
  UNSURE: whether macOS 27 still delivers task control ports in exception messages to an unprivileged handler
          for a non-hardened ad-hoc process, and whether the shim/framework python reset exception ports.
  Run that decides: a test caller that sets task_set_exception_ports(EXC_MASK_ALL, EXCEPTION_DEFAULT) on itself,
          execs the launcher with RLIMIT_STACK small, and logs whether its handler receives a task port for the
          refund child. Fix: in _child_setup reset task exception ports to MACH_PORT_NULL (ctypes
          task_set_exception_ports) and set fixed rlimits (STACK, DATA, CPU, NOFILE, FSIZE).
  Matrix: add a row (inherited exception/special ports) = OPEN. N19 "not enforced" must also name this path.

F-07  LOW   launcher.py:377-380
  What  : (a) The return value of os.write is ignored; pending is advanced by n, not by the bytes written. A short
          write (possible for n > PIPE_BUF when a signal with a handler interrupts after a partial transfer)
          would silently drop request bytes. (b) On BrokenPipeError the launcher sets pending to empty and goes
          on to decide, instead of REFUSED. N20 ("the bytes on fd 0 are exactly req", ENFORCED) is then false for
          that run, and the run can still reach decide_from_result.
  Impact: by reading, a wrong AUTHORIZED needs the program to print the full echo frame from a partial request,
          which the honest parser should not do; so safe in practice, but the ENFORCED claim is not enforced.
  Matrix: N20 -> "ENFORCED except on EPIPE/short write (not refused)"; fix: use n = os.write(...) and REFUSE on
          EPIPE.
