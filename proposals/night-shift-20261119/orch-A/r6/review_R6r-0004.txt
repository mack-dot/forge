D-2 INSTREAM_BUFFERED_FD_V_def: = INSTREAM_BUFFERED_FD (TextIOProofScript.sml 1009-1018) with the existential bcontent
    exposed through INSTREAM_BUFFERED_BL_FD (1020-1029) and pinned to LENGTH 4100. STRONGER than the original
    (INSTREAM_BUFFERED_FD_V_IMP proves V ==>> original). 4100 is inside the original bounds 1028 <= L < 65536
    (instream_buffered_inv_def 956-968), so it is satisfiable. 4100 = min 65535 (max (4096+4) 1028) =
    openStdIn's array (TextIOProgScript.sml 297-305). No theorem here proves that openStdIn produces it.
D-3 INSTREAM_STR_V_def, D-4 INSTREAM_STRP_V_def: the originals INSTREAM_STR (5773-5780) and INSTREAM_STR' (5811-5819)
    with only INSTREAM_BUFFERED_FD -> INSTREAM_BUFFERED_FD_V. Text compared: identical otherwise.
T1 read_event_ok_read_into: the unfolding of read_event_ok into the H_inv form of read_into_spec_V. Correct, not vacuous.
T2 read_event_ok_refund: |- read_event_ok refund_valid_event 0. THIS IS the implication "read_event_ok => valid read
    event" for fd 0. refund_valid_event_def (attempt-0001/L2c-0001/stdout.log:35-43) read clause: ab of LENGTH 4100,
    TAKE 2 ab = n2w2 4096, LENGTH nb = LENGTH ab, HD nb = 0w, fd byte n2w8 0. read_event_ok gives exactly ab =
    n2w2 4096 ++ h3::h4::rest with LENGTH rest = 4096 (so 4100) and LENGTH nb = 4100. So the implication is NOT missing.
    Limit: it holds only for fd with n2w8 fd = n2w8 0 (in practice fd 0); a caller must show that the instream's fd is 0.
T3 STD_streams_fd0: wfFS /\ STD_streams ==> fd 0 has content and ReadMode. Not vacuous (standard initial fs). It closes
    item "descriptor-0 lemma" of the R6ffi and R6w reviews.
T4 INSTREAM_STRP_V_F_F: copy of the [local] INSTREAM_STR'_F_F (5821-5826). Pure rewriting lemma.
T5 INSTREAM_BUFFERED_FD_V_IMP, T6 INSTREAM_STR_V_IMP: weakening V ==>> standard. Right direction. There is NO converse
    (standard ==>> V is false in general), so no existing CakeML spec that RETURNS INSTREAM_STR can be reused to
    produce INSTREAM_STR_V: every caller on the read path needs its own V-spec.
T7 read_into_spec_R: = read_into_spec_V (R6ffi-0002) with H_inv replaced by n = LENGTH rest, LENGTH rest = 4096,
    read_event_ok Inv fd. Compared with the CakeML read_into_spec (2132-2149): same pre/post with IOx fs_ffi_part ->

    pure part (get_fd_content = NONE \/ mode <> ReadMode) is false, so the spec says no exception occurs. Specialised
    to one buffer shape (4096 + 4 bytes, n = 4096); not vacuous: refillBuffer_with_read_spec_V uses it in both branches
    (stdout STEP_USED 11 and 21).
T8 refillBuffer_with_read_spec_V: built by term surgery from the STORED TextIOProof.refillBuffer_with_read_spec
    (r6r_common.sml:172-177): all original hypotheses kept, then + LENGTH bcontent = 4100 + read_event_ok Inv fd, and
    IOFS -> IOFS_V Inv in pre and post. Compared with 2725-2743: same shape. The event property is NOT a separate
    conjunct; it is carried by IOFS_V Inv = IOxV Inv * (iobuff of EXACTLY 2052 bytes) * wfFS (R6ffi-0002 stdout:40-53),

T9 refillBuffer_with_read_spec_STR_V: = refillBuffer_with_read_spec_STR (6824-6831) with STDIO -> STDIO_V Inv,
