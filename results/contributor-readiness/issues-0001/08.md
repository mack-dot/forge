`docs/claims.md` explains C1–C5 with real accept/reject examples, but a PR author only sees the raw gate output.

**Goal:** a readable summary of which claims were established, by which method, and which were not, generated from the evidence bundle (not from the candidate's own code).

**Constraints:** the report must be derived only from trusted gate output; it must not run candidate code; and it must not need write permissions in the job that reads the candidate. Start with a local script that turns `build/*.json` evidence into Markdown, plus tests with real accepted and rejected bundles.

**Done when:** the script produces correct reports for an accepted ledger and for each planted bug.
